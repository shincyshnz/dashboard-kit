# Changelog

## @dashboard-kit/ui 0.4.0, @dashboard-kit/starter 0.2.0 — Phase 2, Step 5 (starter sync)

- New `pnpm registry:sync [name…]` (`packages/ui/scripts/sync-registry.mjs`): copies registry items and their registry dependencies into `apps/starter`, maps files by type through `components.json` aliases, and adds missing npm dependencies with the registry's version range
- `pnpm registry:check` now also runs `registry:sync --check`, failing when a starter copy drifts from `packages/ui` or the starter lacks a needed npm package
- Starter: header theme picker is now the registry Select (synced, with `@radix-ui/react-select`) instead of a native `<select>`
- Docs: "Keeping the starter in sync" in `docs/REGISTRY.md`; new rule 7 in `AGENTS.md`; `PROJECT-STRUCTURE.md` rule 3 clarified; learning note `docs/learning/phase-2-step-5-starter-sync.md`

## @dashboard-kit/ui 0.3.0 — Phase 2, Step 4 (primitives)

- Added 20 registered primitives: input, label, textarea, select, checkbox, switch, dialog, sheet, dropdown menu, popover, tooltip, tabs, table, skeleton, separator, avatar, Sonner, sidebar, breadcrumb and command
- Added a Storybook story for each primitive, including disabled, invalid, empty, collapsed and directional examples where supported
- Added Radix UI, cmdk, Sonner and Lucide dependencies to the registry source and declared each component's install requirements

## @dashboard-kit/config 0.2.0 — Phase 2, Step 3 (token audit lint rule)

- New ESLint rule `dashboard-kit/no-raw-design-values` (`@dashboard-kit/config/eslint/token-audit`): rejects Tailwind palette classes (incl. `black`/`white`) and arbitrary colour, radius, shadow and font values, through any variant
- `packages/ui` now has `eslint.config.js` and a `lint` script, so `pnpm lint` audits every registry component
- RuleTester suite under Vitest (`pnpm --filter @dashboard-kit/config test`)
- `docs/REGISTRY.md` styling rules now point to the rule; learning note `docs/learning/phase-2-step-3-token-audit.md`

## @dashboard-kit/tokens 0.3.0 — design tokens in DTCG JSON (ADR 0011)

- Token values moved from YAML in `DESIGN.md` to `design-tokens.json` (DTCG: groups, `$value`, inherited `$type`, `$description`, `{aliases}`, `$extensions`)
- Tenant themes are `themes/<name>/design-tokens.json` (overrides only); aliases resolve after merging; old theme notes became `themes/<name>/README.md`
- Values accept readable CSS strings (house style) or DTCG object forms (colour, dimension, duration, shadow, cubicBezier, fontFamily)
- `DESIGN.md` rewritten as the design guide: intent, rules, agent instructions, changelog, and token tables generated by `pnpm tokens:docs`
- Generated JSON Schemas (`packages/tokens/schema/`) give editor autocomplete; validated with ajv
- `pnpm docs:check` now also fails on stale DESIGN.md tables or schemas; watch mode refreshes the tables
- Clearer errors: JSON syntax errors with line/column; validation errors use the JSON paths you edit
- Importer writes into the JSON, keeps `$description`s, normalises values to strings
- 30 tests (was 18); generated CSS/JSON verified byte-identical to the YAML version
- ADR 0002 superseded by ADR 0011; learning note `docs/learning/dtcg-json-tokens.md`

## 0.2.0 — Phase 1 (design token system)
